# 多项目 + 素材库管理 UI 设计 spec

日期：2026-10-14
状态：已确认（brainstorm 收口）
范围：Spec ①（共两个）。Spec ②「图片上轨」（`PlanClip.source` 枚举 + 引擎静态帧合成）另行立项，本 spec 不含。

## 背景

App 当前为单草稿形态（单个 `draft.json` + 素材库目录），导入即上轨。本 spec 把 App 演进为「多项目 + 全局素材库」：素材实体与剪辑工程解耦，项目只持有素材引用。这与公约 §3「素材引用走登记表」是同一抽象的显性化；素材库同时是剪辑 Agent 可枚举、可引用的确定性资源池。

## 决策汇总（brainstorm 已拍板）

1. 首页 = 项目列表（单列大卡），剪辑页是导航栈推送页；新建项目的唯一入口在项目列表
2. 素材库为 **App 级全局库**，入口两处：项目列表导航栏 + 剪辑页操作条
3. 引用关系**不在素材侧存储任何反向数据**（不存计数也不存列表），用到时扫描全部 project.json + 当前打开项目的内存 plan 读时计算
4. 素材库内按类型分 tab（视频/图片/音频）；本期上轨仅视频（图片上轨 = Spec ②；音频维持「音频整体后置」决策）
5. 素材无「复制」功能；素材多选模式下只有「删除」一个操作
6. 时间线本期简化：水平排布、每段固定宽度、右缘浮动「＋」；精细化留给时间线专项
7. 导出双概念文案分离：剪辑页「导出成片」（现有 ExportPanel 逻辑不变），项目列表「导出工程包」
8. 工程包导出/导入成对做；素材入库统一按 SHA-256 内容哈希去重
9. 旧 `draft.json` 启动时自动迁移为「未命名项目」

## 持久层

### 目录布局（`Application Support/Jangy/`）

```
Projects/<projectUUID>/project.json   ← 格式 = 现 EditPlan JSON，不变（不动清单遵守）
Projects/<projectUUID>/cover.jpg      ← 封面缓存（第一片段首帧）
Assets/                               ← 全局素材文件目录（现状不变）
library.json                          ← 全局素材登记表（AssetItem 数组 + sha256 字段）
```

### 三条核心决策

- **plan 格式不变**：project.json 即现 EditPlan JSON（含 `plan.assets` 项目内登记表）。CLI 链路零影响；项目自包含，工程包导出 = project.json + 引用的素材文件
- **双登记是有意冗余**：`library.json` 管素材实体（kind/文件名/来源/导入时间/sha256），`plan.assets` 管项目引用。删除素材只动 library；plan 侧由完整性校验兜底
- **无项目索引文件**：项目列表 = 扫描 `Projects/` 目录读各 project.json 派生（名称/时长/封面缓存）。项目量级几十个，不引入索引双写

### AssetItem 变更

新增 `sha256: String?` 字段（Codable 向后兼容，缺省 nil），入库时计算。

### DraftStore → ProjectStore

L2 持久化层演进：load / save / delete / duplicate / rename / scanProjects / 旧 draft.json 迁移。现有防抖 autosave 平移为按项目保存。AppModel 从「单草稿」变「当前打开的项目」：打开/切换项目 = 换 plan 重载 EditStore，撤销栈清空。

## 项目列表页

- **布局**：单列大卡 = 封面 + 项目名 + 时长 + 最后修改时间；按修改时间倒序
- **导航栏**：标题「项目」；右侧「素材库」「⋮ 更多」（内含「导入工程包」）；「多选」
- **新建**：底部「＋ 新建项目」→ 创建空白项目并直接进入剪辑页；默认命名「未命名项目 N」。空态时页面中央显示大引导按钮
- **单项目操作**（卡片 ⋯ / 长按）：重命名 / 复制 / 查看信息 / 导出工程包 / 删除
- **多选模式**：底部操作条 = 删除 / 复制 / 导出工程包（选中几个就生成几个 zip，一次分享面板带出）；重命名与查看信息仅单选可用
- **查看信息**：项目名、时长、片段数、引用素材数、创建/修改时间、引用素材体积和
- **删除**：二次确认；只删 project.json + 封面缓存，**不动素材库**（素材生命周期由素材库页管理，与项目解耦）
- **复制**：复制 project.json 生成新项目（名称加「副本」后缀）；全局库下为 O(元数据)，不拷素材

## 素材库页

- **结构**：顶部 tab（视频/图片/音频）+ 三列网格，按导入时间倒序。视频/图片格 = 缩略图（视频带时长角标）；音频格 = 图标 + 文件名 + 时长。未来贴纸/特效/滤镜/转场直接加 tab
- **导入**：右上「导入」菜单（从相册 / 从文件）。相册通道支持视频+图片；文件通道放开 `UTType.movie / .image / .audio`。**导入只入库不上轨**，完成后留在素材库页并高亮新素材；同内容（SHA-256）重复导入只存一份、复用 assetID
- **点素材** → 素材预览页
- **「＋」快捷上轨**：仅从剪辑页进入时显示，且**本期仅视频 tab 的素材格显示**（图片上轨属 Spec ②，音频维持后置——两类格子不出现 ＋）。点击 = 素材**全长**追加到当前项目时间线末尾（登记 + 追加片段同一次 `EditStore.apply`，公约 §3 不变），toast「已添加到时间线」，**留在素材库页**继续挑选
- **多选模式**：仅「删除」。删除前引用扫描（全部 project.json + 当前打开项目的内存 plan）：
  - 均无引用 → 二次确认后删（文件 + library.json 登记同步清理）
  - 有引用 → 弹窗列出引用项目名，**不允许删**，提供「改为只选未引用素材」
  - 扫描中遇损坏的 project.json → 拒绝删除并报原因（保守原则）
- **空态**：当前 tab 无素材时中央「＋ 导入素材」引导
- 打开素材库页时校验 library.json 与 Assets/ 目录一致性，漂移显式报告

## 素材预览页

三类共用骨架：导航（返回 + 「信息」）→ 内容区 → 底部「添加到时间线」（按类型与语境决定是否显示）。

- **视频**：AVPlayer 播放 + trim 条（**样式参照 iOS 相册视频裁剪**：胶片条缩略图 + 首尾把手，实时显示「已选 起~讫 / 总时长」）。「添加到时间线」以 trim 区间上轨；不 trim = 全长
- **图片**：全屏预览（捏合缩放）+ 展示时长选择（2s / 3s 默认 / 5s / 自定义 0.5s~30s 步进）。**本期不显示添加按钮**（图片上轨属 Spec ②，时长选择器本期一并隐藏，预览页只承担查看 + 信息）
- **音频**：播放 + 波形示意；无添加按钮（维持音频后置）
- **信息面板**（右上，半屏 sheet）：分辨率/时长/文件大小/格式/导入时间/**引用项目列表**（与删除保护共用同一扫描函数）
- **预览页不提供删除**；删除唯一入口 = 素材库多选

## 剪辑页改造

- 导航栈推送页：导航栏 = 返回（回项目列表）+ 项目名（点击可重命名）
- 操作条：撤销 / 重做 / 字幕 / **素材库**（替代原「导入」）/ Agent / **导出成片**
- 删除：「新建」按钮、`resetDraft`、新建确认弹窗整体移除
- 时间线：固定宽度段水平排布；「＋」为**浮动在可见区域右缘**的悬浮按钮（不随轨道滚动），点击推进素材库页（剪辑页语境）；空时间线时预览区中央额外显示「＋ 添加素材」大按钮
- 导入进度等反馈组件保留，触发源挪到素材库页
- Agent 入口与行为不变（操作当前打开项目的 EditStore）

## 工程包导入导出

- **格式**：`<项目名>.jangyproj.zip`：
  ```
  project.json        ← 原样打包（自包含）
  assets/<fileName>   ← 仅本项目引用的素材（按 plan.assets 收集）
  manifest.json       ← 格式版本 + 导出时间 + App 版本
  ```
- **导出**（项目列表，单个或多选）：收集引用 → 从全局库拷文件 → zip → 系统分享面板。引用素材文件缺失时**报错并列出缺失项，不静默跳过**
- **导入**（项目列表 ⋮ 更多 → 导入工程包，文件选择器收 zip）：解包到临时目录 → 校验 manifest 版本 + project.json 可解码 + 素材完整 → 素材按内容哈希入库（已有同内容则复用 assetID；同 assetID 不同内容则生成新 assetID 并改写 plan 引用）→ 生成新项目（新 projectUUID，名称冲突加后缀）→ 列表顶部出现。**全部校验通过才落库，失败不产生半成品项目**

## 错误处理

- 打开项目时跑按项目的完整性校验（verifyDraftIntegrity 扩展），问题显式报在剪辑页顶部
- 导入部分失败：成功的入库，失败的逐条列明原因
- iCloud 相册素材导入进度沿用 kadr-photos 现有能力

## 测试策略

核心层单测（JangyCore），UI 层真机手动验证：

- ProjectStore：建/删/复制/重命名/列表扫描/旧 draft.json 迁移
- 素材库登记：library.json 读写、SHA-256 去重（同内容复用 assetID）
- 引用扫描：assetID → 引用项目列表（含内存 plan）；损坏 project.json 触发保守拒删
- 删除保护：有引用拒删；无引用删除后文件 + 登记同步清理
- 工程包：导出 → 导入往返等价；assetID 冲突改写；损坏包/版本不兼容报错
- 底线：现有 125 测试全绿；CLI 零改动

## 明确不做（本期）

- 图片上轨、音频上轨（Spec ② / 音频后置决策）
- 素材复制、素材重命名、素材侧任何反向引用存储
- 时间线精细化（缩放/拖拽排序/可变宽度）
- 剪辑页内新建项目、清空时间线
- 贴纸/特效/滤镜/转场的素材化（tab 结构已预留）
